# Lab 15: Spring CRUD with MySQL

My lab 14 Course API (same endpoints, status codes and validation), moved from the H2 in-memory database to a MySQL server on Aiven.

## What changed from lab 14

| File | H2 (lab 14) | MySQL (lab 15) |
|---|---|---|
| `pom.xml` | `com.h2database:h2` | `mysql:mysql-connector-java:8.0.33` |
| `schema.sql` | `GENERATED BY DEFAULT AS IDENTITY` | `AUTO_INCREMENT`, and `DROP TABLE IF EXISTS course` first, because MySQL keeps the data between runs |
| `application.properties` | nothing | MySQL driver, `spring.sql.init.mode=always` (runs `schema.sql`/`data.sql` on a non-embedded database too), and imports `db.properties` |

The Java code is the same as lab 14 (only the package name changed).

## Connecting to your Aiven database

The connection details are **not** in `application.properties`, so the Aiven password never gets pushed to GitHub. They go in `src/main/resources/db.properties`, which is in `.gitignore`:

1. On Aiven, create the free MySQL service and, in the **Databases** tab, the database `se411db`.
2. Copy `src/main/resources/db.properties.example` to `src/main/resources/db.properties`.
3. Fill in the host, port and password from the service's **Overview** page:
   ```properties
   spring.datasource.url=jdbc:mysql://YOUR-SERVICE.aivencloud.com:PORT/se411db?sslMode=REQUIRED
   spring.datasource.username=avnadmin
   spring.datasource.password=YOUR_AIVEN_PASSWORD
   ```

Without `db.properties` the app stops at startup with an error saying the file does not exist.

Run: `mvn clean spring-boot:run` (or Run As → Spring Boot App in Eclipse). The API is at http://localhost:8080/api/v1/courses. Every start drops the table and reloads the 7 courses of `data.sql` (ids 1–7).

## Testing with PutMan (Eclipse)

Install: Help → Install New Software → Add → Location `https://civerooni.github.io/putman-site/` → select Putman → Finish → restart Eclipse. Open it with Window → Show View → Other → Putman → Putman.

For POST and PUT, set the body to JSON (`Content-Type: application/json`). Send them in this order after a fresh start:

| # | Request | Body | Expected |
|---|---|---|---|
| 1 | `GET /api/v1/courses` | | 200, 7 courses |
| 2 | `GET /api/v1/courses/5` | | 200, SE411 |
| 3 | `GET /api/v1/courses/99` | | 404 |
| 4 | `POST /api/v1/courses` | `{"code":"SE412","name":"Software Testing","description":"Testing techniques","credits":3}` | 201, `Location: /api/v1/courses/8` |
| 5 | `POST /api/v1/courses` | `{"id":5,"code":"X1","name":"Duplicate","credits":3}` | 422 |
| 6 | `POST /api/v1/courses` | `{"id":-3,"code":"","name":"A","credits":11}` | 400, all four validation errors |
| 7 | `PUT /api/v1/courses/5` | `{"code":"SE411","name":"Software Construction II","description":"Updated","credits":4}` | 204 |
| 8 | `GET /api/v1/courses/5` | | 200, the new name |
| 9 | `DELETE /api/v1/courses/7` | | 204 |
| 10 | `DELETE /api/v1/courses/7` | | 404 |

After these, the MySQL client in VS Code shows the same rows in the `course` table, which proves the data is in MySQL and not in memory.
